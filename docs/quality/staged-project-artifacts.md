# Staged isolated project commands

Docker mode now prepares a private temporary copy inside the existing command gate. Source, credentials in .env files, .git, node_modules, existing build outputs and prior artifact runs are excluded as appropriate. Writable project permissions apply only to the temporary copy; original source ownership is unchanged. Project dependencies must already be supplied by the pinned runtime image; there is no implicit dependency installation/network access.

On successful command exit, dist/build outputs are validated against symlinks, special files and size limits, then copied into a new immutable-by-convention .vf-builds/run-* directory. Existing source and build folders are never replaced. The artifact metadata includes the source fingerprint and is returned to callers and saved in verification checks. Both pre/post-copy source fingerprints must match; concurrent source changes reject stale results. Staging is removed after success/failure. Artifacts are not automatically served or installed; consumers must use returned artifact paths and retain product acceptance checks. This is a controlled export, not an overwrite of the user's source.
