## VillaForge 1.62.0

Full-Stack-Engine als Agentforge2-Worker: aus einem Satz Beschreibung entsteht ein
verifiziertes Web-Produkt mit Oberflaeche, API, Datenmodell, Auth und Rollenrechten.

- Neuer Dienst `server/fullstack/`: Planner (Blueprint mit `project_manifest.json`), Executor (Dateibaum),
  Express-Stufe (Syntax, Vertraege, echte API-Tests in der Sandbox), Reviewer (begrenzte Selbstkorrektur).
- Erzeugt werden Client (React + Tailwind, Seiten, Komponenten, Services, Hooks), API (REST je Domaene,
  Validierung, standardisierte Fehler), Datenmodell (Prisma-Schema, Migration, Seed), Auth (HS256-JWT,
  scrypt-Hashing) und Rollenrechte (User/Manager/Admin) - jede Route traegt ihre Zugriffsstufe.
- Ereignisse auf `agentforge:events:stream`: `PROJECT_PLANNED`, `SCAFFOLD_GENERATED`, `CONTAINER_TEST_PASSED`,
  `CONTAINER_TEST_FAILED`, `CHECKPOINT_SAVED`, `STREAM_COMPLETE`, `STREAM_FAILED` - ausschliesslich Metadaten,
  kein Auftragstext, kein Dateiinhalt. Checkpoints laufen hash-verkettet ueber die bestehende Aufgaben-Datenbank.
- Worker `npm run worker:fullstack` liest Bauauftraege aus dem Stream, bestaetigt erst nach Abschluss, holt
  haengende Pakete zurueck und schreibt seinen Zustand nach `server/data/fullstack/worker-health.json`.
- Ehrliche Grenze: ein Bau ohne bestandene Pruefung endet als `STREAM_FAILED` mit Befund; ohne verfuegbare
  Sandbox gilt er als nicht verifiziert statt still auf dem Host zu laufen.
- Tests: `server/tests/fullstack-manifest|emit-verify|engine|worker.test.mjs` (27 Faelle, inklusive
  Reparaturpfad, Abbruchpfad und echtem Lauf der generierten API mit 8 Tests).
- Details: `docs/fullstack-engine.md`. Version 1.62.0 in Hub, npm und Android synchron.
