## VillaForge 1.66.0

Das Villa-Audit nennt bei roter Produktabnahme den Grund, ohne Interna zu veroeffentlichen.

- `assessVillaConfiguration` liefert je Villa `productEvidence.blockerCodes`: stabile Codes wie
  `evidence_stale`, `build`, `tests`, `smoke`, `no_implementation`, `open_tasks`, `failed_tasks`.
  Unbekannte Gruende werden zu `other`, damit ein neuer Blocker nie stillschweigend verschwindet.
- Der Bericht (Artefakt) enthaelt Codes, keine Blockiertexte, keine Pfade, keine Projektidee.
  `aggregateProductBlockers` zaehlt sie im Berichtsursprung; das Workflow-Protokoll gibt nur
  dieses Aggregat aus, weiterhin ohne Villa-Kennungen.
- Anlass: Das Audit vom 2026-11-10 meldete 24 von 26 Villen als `product_acceptance` blockiert,
  ohne dass aus dem Bericht hervorging, ob Baustufe, Tests, Smoke, fehlende Implementierung oder
  ein veralteter Pruefnachweis die Ursache ist.
- Keine Schwelle und kein Gate wurde gelockert: die Abnahme bleibt rot, solange sie nicht belegt ist.
- Sieben neue Tests fuer Code-Zuordnung, Sortierung, Bericht ohne Texte und das Aggregat.
- Version 1.66.0 in Hub, npm und Android synchron.
