## VillaForge 1.64.0

Integrationen in bestehende Repositories laufen ueber Feature-Branch und Pull Request (Issue #135).

- Eine Villa mit belegter Repository-Bindung veroeffentlicht nicht mehr ueber ein neu angelegtes
  Produkt-Repo mit Force-Push auf `main`. Der Weg ist jetzt: Feature-Branch
  `villaforge/integration-<villaId>-<slug>` anlegen, committen, ausschliesslich diesen Branch
  per explizitem Refspec pushen, danach einen Pull Request gegen den belegten Zielbranch oeffnen.
- Der Zielbranch kann nie Arbeitsbranch sein: ist der Feature-Branch gleich dem Zielbranch,
  bricht der Lauf vor dem ersten Git-Befehl ab. Es gibt keinen `--force`-Push mehr.
- Kein PR ohne Nachweis: rotes Qualitaetstor, fehlende Aenderungen, fehlender Git-Checkout oder
  fehlendes Token beenden den Lauf mit klarer Stufe (`gates`, `commit`, `checkout`, `config`)
  statt mit einem leeren Pull Request.
- Ein bereits vorhandener Pull Request (HTTP 422) ist ein eigener Zustand und kein stiller Erfolg.
- Zugangsdaten werden aus Git- und HTTP-Fehlermeldungen entfernt (`x-access-token:…@`, `ghp_…`,
  `github_pat_…`).
- Ungebundene Villen behalten den bisherigen Weg in ihr eigenes Produkt-Repo.
- Neues Modul `server/integration-publish.mjs`, Regressionstest
  `server/tests/integration-publish.test.mjs` (10 Faelle mit injiziertem `exec`/`fetch`, ohne Netz
  und ohne echtes Git).
- Version 1.64.0 in Hub, npm und Android synchron.
